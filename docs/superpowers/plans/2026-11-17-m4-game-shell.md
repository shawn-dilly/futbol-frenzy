## Scope decisions

- Six fictional teams; choose either side in setup, default distinct opponents. Ratings are visible and have named, tested effects on both human and CPU play. Power maps linearly to 0.8–1.3. Keep tuning modest and data-driven, not a new balance gate.
- Lengths: two 120s or 240s halves, or first to five. First to five has no clock expiry and ends immediately on the fifth goal; provide a halftime at the first team reaching three, once, unless that goal already ends the match. Draws in timed Cup matches eliminate the player; wins advance through each other team once in stable table order, loss or draw ends the run. No persistence across reloads is required.
- Automatic substitution at lethal damage uses one of three team reserves, replacing the same player slot with fresh health and reset transient state after the hit; keeper included. Without reserves, health clamps to 1 and remains Dazed under existing rules. Count each lethal hit as a KO. Preserve existing live health regeneration and halftime healing deviation.
- Stats count shots when a shot kick occurs, big hits when a big hit lands, KOs on lethal hits, and steals when a hit causes an opposing carrier to drop the ball; report per-team cumulative match totals. Hit of the half is highest damage landed in that half, earliest tick then event order breaks ties; show an explicit no-hit state. Replay a short window around that hit from seed and recorded per-tick inputs, with deterministic reconstruction including CPU decisions; presentation effects are cosmetic.
- Pause and halftime stats stop sim ticks until explicit resume. Replay uses separate reconstructed state and never changes the live match, RNG, recorded inputs, stats or cup session. New match, quit, restart, visibility changes, and scene shutdown must clear stepper backlog, input/listeners and transient effects; Cup progression is owned outside the match scene. Query demo and test parameters remain usable, with demo bypassing shell.

## Interfaces

These are the shared public contracts; implementation may add private helpers. Sim types/functions below are exported through `src/sim/index.ts`; presentation imports only that entry point. All arrays indexed by team use `TeamId` order.

- `src/sim/types.ts` and `setup.ts`: add `Ratings { speed: number; power: number; skill: number; dirty: number }`, each normalized to 0–1, and optional `MatchConfig.ratings: [Ratings, Ratings]` and `MatchConfig.targetGoals?: number`. `createMatch` owns normalization: missing ratings use neutral 0.5 for every field; clamp supplied values to 0–1; omitted target retains timed behavior. Its state config contains the normalized defaults. `halfSeconds`, seed, human and level retain existing semantics. Content's six team records supply normalized ratings; setup maps selected records into plain config values.
- `src/sim/types.ts`: `TeamStats { shots: number; bigHits: number; kos: number; steals: number }`; add `stats: [TeamStats, TeamStats]`, `reserves: [number, number]`, and `halfHits: [HalfHit | null, HalfHit | null]` to `MatchState`. `HalfHit { tick: number; eventIndex: number; damage: number }` identifies a hit in the events emitted by the step ending at `tick`; compare damage descending, tick ascending, event index ascending. Initial stats are zero, reserves three, hits null. Sim alone updates them. A hit record locates replay history, not a mutable event reference.
- `src/game/cupSession.ts`: pure session transitions own `CupSession` (selected team, settings, ordered opponents, current rung, current match ID, consumed match IDs and status). `startCup`, `consumeResult(session, matchId, result)`, `retryCup`, and `quitCup` return new session values. Only a result for the active ID in an active session is consumed; duplicates and stale IDs are no-ops. Win advances once or completes; draw/loss ends the run. Retry starts the same rung with the same settings and a fresh ID. Advancing also assigns a fresh ID. The session owner must supply a fresh non-empty run ID to every `startCup` call; the future shell should use a monotonic counter. Match IDs unambiguously combine that run ID and a counter and must be unique across runs and within a session, including retries. Pure session logic uses no wall clock. Replay return never calls `consumeResult`.
- `src/game/replay.ts`: `ReplayRecord { config: MatchConfig; inputs: [PadInput, PadInput][] }` owns a copied initial normalized config and copied inputs per executed step. Input index `i` produces the state/events after step `i + 1` (initial tick is zero); a `HalfHit.tick` maps to index `tick - 1`. Replay reconstruction starts with `createMatch(config)`, steps recorded inputs and exposes a window clipped to recorded ticks; include the selected hit even at either boundary. No UI time or Continue command is recorded. Reconstruction never writes to the live state or record.
- `src/game/launch.ts`: `MatchLaunch { config: MatchConfig; mode: 'demo' | 'direct' | 'friendly' | 'cup'; matchId: string | null; mute: boolean }` is passed to `MatchScene.init`; shell/session owns Cup identity and result consumption, match scene owns its live state and replay record. Each launch creates fresh sim stats, reserves and history. URL parsing maps `demo=1` to demo and `match=1` to direct human play (demo takes precedence); preserve seed, mute, half, level and level2 with the existing team mapping. Shell setup constructs the same launch contract.

Halftime is a presentation gate: after the step first enters `halftime`, shell sessions stop calling `step` and clear the fixed-step backlog. Continue dismisses the gate and resumes stepping the **existing** sim halftime countdown; presentation never changes `half`, `phase` or `phaseTicks`. Gate once per halftime entry so countdown ticks do not reopen it. Demo and direct test routes retain automatic countdown. Replay steps continuously through recorded halftime countdown ticks, excluding wall-time pauses.
